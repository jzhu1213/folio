# Phase 5.4 — Category Rollover

- **Existing logic:** The project already had a category rollover preference and calculation helper, but it was dormant: category rows and progress bars did not use it. This phase activates the visible carry-forward behavior.
- **Calculation and schema:** No schema change was required. The app now fetches the completed preceding month’s existing `budgets` rows alongside current-month rows. For each category, `available this month = current monthly_limit + min(max(previous monthly_limit - previous spent, 0), previous monthly_limit × 0.5)`. The established 50% carry cap is retained. An explicit prior opt-out (`folio_category_rollover_enabled = false`) is respected; otherwise rollover is on by default.
- **Detail view:** A nonzero example with a $100 prior cap and $60 left carries $50 into a $100 current cap, showing: Base monthly limit $100; Carried over +$50; “Includes $50 carried over from last month”; Available this month $150. The bar fills against $150. With no carry, only Base monthly limit and Available this month appear—there is no noisy $0 line.
- **Lifecycle decisions:** An archived category’s budget rows and carry are never deleted; if restored, the same derived historical carry is available. A mid-month limit change applies immediately to the current month’s base cap, while its carry remains fixed from the completed prior month, avoiding retroactive rewriting of past carry.
